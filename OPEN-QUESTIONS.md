# Open questions

Judgment calls made while building the components in COMPONENTS.md without stopping to ask.
Each entry: what was unclear, what was chosen, and why. Review these and tell me which to change.

| # | Component | Question | What I chose | Why |
|---|---|---|---|---|
| 1 | All | Figma frames have fixed example widths (Tooltip 320, fields 352, Alert/Accordion/Dialog 560, Table 1120px) with no spacing token. | Components are fluid (`w-full` or hug content) and the container sets the width. Where a maximum width matters I used Tailwind's built-in container sizes: Tooltip `max-w-xs` (320px), Dialog `max-w-xl` (576px). | No token exists for these widths, and they look like artboard sizes rather than component rules. Built-in container sizes aren't arbitrary values. |
| 2 | Tooltip | Figma doesn't say where the tooltip sits or how it's positioned. | Above the trigger, centered, 8px gap (Scale/200), flipping below when there's no room. Placed with a few lines of JS on a `popover="manual"` element. | CSS anchor positioning isn't in every browser we can assume yet, and JS positioning is small and predictable. |
| 3 | Tooltip | Should mouse focus (clicking the trigger) also show it? | Shown on hover and on keyboard focus (`:focus-visible`) only. | Matches the spec ("hover and keyboard focus") and avoids a tooltip popping up on every click. |
| 4 | Global | Stories had a transparent page background, so on a dark OS theme Storybook drew them on a dark canvas. | `styles.css` now sets `body` to `Surface/page` background and `Text/body` color (separate commit). | The design system is light-only and Figma has a Surface/page token for exactly this. |
| 5 | Input | Input needs icons inside the box (leading icon, error indicator), so it can't be a bare `<input>`. | `Input()` returns the styled box (`<div>`) with the native `<input>` inside, available as `box.input`. | Consistent return type whether or not icons are shown. Field finds the native control inside. |
| 6 | Input | Figma's focus state is a 2px Primary/700 border; the Button focus ring (outline outside) doesn't apply. | Focus uses `focus-within`: the 1px border turns Primary/700, plus a 1px inset ring, for 2px without moving the text. Hover is suppressed while focused. | Matches Figma exactly. Text fields show focus on any focus (not only keyboard), which is standard for inputs. |
| 7 | Input | Figma has no "Error + Focus" state. | An invalid input keeps its Error/700 border and gets an Error/700 inset ring when focused. | Keeps the error visible while the user corrects it. |
| 8 | Checkbox, Radio, Switch | Figma has no hover state for these. | No hover style; focus fills the whole row (Primary/100 + 2px Primary/700 inside border), as Figma draws. | Follows Figma; adding a hover state would be inventing design. |
| 9 | Switch, Radio | The switch track radius is a raw 12px in Figma (no variable), and the radio circle has no radius variable. | `rounded-full` (Tailwind's built-in pill/circle). | Same shape, and no radius token is meant for pills. A `Border radius/full` variable in Figma would make it explicit. |
| 10 | Tab | Figma's tab is a fixed 180px wide with no padding; there's no width token. | Tabs hug their label with 24px side padding (`px-600`). | Fixed widths break with longer labels; 24px is the nearest spacing token that keeps short labels close to Figma's look. |
| 11 | Tab | Figma has no focus state for tabs. | A 2px Primary/700 ring drawn inside the tab (`-outline-offset-2`). | Tabs sit edge to edge, so an outside ring would be cut off by neighbors. Same color and width as the Button ring. |
| 12 | Accordion | Figma swaps chevron-down for chevron-up when open. | One chevron-down that rotates 180° when open (`motion-safe` transition). The default disclosure marker is hidden with `list-none`. | Matches decision 7's note; `list-none` hides the marker in current browsers without an arbitrary variant. Very old Safari versions may still show a triangle. |
| 13 | Pagination item | How should a disabled page link be marked up? | An `<a>` with no `href`, plus `role="link"` and `aria-disabled="true"`. | Keeps it in the same place for screen readers while making it inert. |
| 14 | Table cell | Figma left-aligns every header, including the numeric "Seats" column. | Numeric columns right-align their header too (`align: "right"`). Body numeric cells use tabular figures. | A left-aligned header over right-aligned numbers is hard to scan; this is a small, common correction. |
| 15 | Label | Figma's help icon is 16px, below the 24px minimum target size (WCAG 2.5.8). | The help button is 24×24 around the 16px icon, with a negative margin so the label row stays 20px tall as in Figma. Its focus ring hugs the 24px circle (no offset). | Meets the target size without changing the layout. |
| 16 | Label | Should the required "*" be read out? | The "*" is `aria-hidden`; the control's `required` attribute is what screen readers announce. | Avoids "star" being read and keeps one source of truth. |
| 17 | Field | The spec uses `help` for the text below the control, and Label also has a `help` (tooltip). | In Field, Text field, Select and Textarea, `help` is the text below the control; the tooltip next to the label is `labelHelp`. | Follows the spec's shared props (label, help, error, disabled, required) without losing the tooltip. |
| 18 | Field | Figma's Error state hides the helper text and shows the error message in its place. Should both be read out? | Error replaces help, visually and in `aria-describedby` (which points at whichever is shown). | Matches Figma; reading hidden help text would confuse. |
| 19 | Field | Figma doesn't show the label color for a disabled field (only the help icon turns grey). | Disabled fields use Text/disabled for the label and help text. | Consistent with every other disabled state in the system. |
| 20 | Select | The chevron needs room on the right: 20px icon + 8px gap = 28px, which has no token. | `pr-700` (32px, nearest token). The placeholder is a disabled first option, shown in Neutral/600 until a value is chosen. | Nearest token; the native select keeps all keyboard and mobile behavior. |
| 21 | Textarea | Figma's box is a fixed 112px tall; no token for that height. | Height comes from `rows` (default 4, about 106px), and the user can resize vertically. | Rows scale with the text style and are the native way to size a textarea. |
| 22 | Field | Figma colors a disabled field's help text Text/disabled (#949494), which is 3.0:1 on white and fails the a11y check (help text needs 4.5:1). | Help text stays Text/body (#3d3d3d) when the field is disabled; the label, box and value still use the disabled tokens. | The zero-violations rule wins. **Figma fix:** keep help text Text/body in disabled fields, or darken Text/disabled. |
| 23 | RadioGroup | No Figma design for the group. | A `<fieldset>` whose `<legend>` looks exactly like Label (paragraph md/medium, Text/headings, red "*"), the radios, then help or error text as in Field. A disabled group uses the native `fieldset disabled`. | Reuses existing pieces so it matches the rest of the form. **Figma fix:** add Form/Radio group. |
| 24 | Tabs | No Figma design for the tab set. | A row of Tabs with a 1px Neutral/200 line under the whole row; panels have 16px top padding and paragraph md text. Selecting follows focus (arrow keys select immediately). | The line anchors the selected tab's 2px underline. Automatic activation suits tabs whose panels are already in the page. **Figma fix:** add Navigation/Tabs. |
| 25 | Pagination | When to switch to an ellipsis? | Up to 7 pages: all shown. More: first, last, and the current page with its neighbors, with "…" for gaps (always 7 slots). The "…" is hidden from screen readers. | A stable width that never jumps as you page; page links still carry "Page N" names. |
| 26 | Dialog | Figma shows no backdrop and no small-screen layout. | Backdrop Neutral/black at 50% opacity. The dialog fills the width up to 576px (`max-w-xl`), centered, with 16px side margins below 640px. | A backdrop is needed to show the page is inert; 50% of an existing token avoids a new color. |
| 27 | Dialog | Which button gets focus when it opens? | The first one, Cancel (native `showModal()` behavior). | Safer for destructive dialogs: pressing Enter right away cancels instead of deleting. |
| 28 | Table | Figma's table has no title, but a `<caption>` is required. | `caption` is a required prop, rendered visually hidden (`sr-only`). | Screen readers announce what the table is about without changing Figma's layout. Easy to make visible later if the design adds a title. |
| 29 | Table | Figma's row has a Selected state, but plain tables have no selection semantics (`aria-selected` only belongs in interactive grids). | `rows[i].selected = true` gives the Primary/100 highlight only, with no ARIA. Hover (Neutral/100) is CSS and doesn't apply to the selected row. | Matches Figma visually without claiming grid behavior we don't implement. Pair it with a Checkbox column if rows need to be selectable. |
| 30 | Table | Should cells accept components, e.g. a Badge in the Status column? | Cell values can be text or any element. The Members story keeps plain text (as in Figma); the Overview shows Badges. | Keeps Table generic. |
